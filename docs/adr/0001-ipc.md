# ADR-0001 — Multi-process + UDS SEQPACKET event bus

**Context.** Perception (capture + Hailo + OpenCV), the NUI engine (pure logic),
and the UI (Qt/Wayland) have very different dependencies and failure modes.

**Decision.** Three separate processes. IPC over `AF_UNIX` `SOCK_SEQPACKET` with a
28-byte header + fixed-layout payloads. Continuous streams drop-oldest; discrete
gestures are reliable.

**Rationale.** Video frames never cross a process boundary (they stay inside
perception); only tiny messages transit, so latency cost is negligible (engine
stage measured ~0.06 ms). Multi-process buys fault isolation and off-target
testability of the engine. SEQPACKET preserves message boundaries → no manual framing.

**Alternatives.** Monolith (rejected: weaker isolation/testability). D-Bus
(rejected: heavy for high-rate flow). ZeroMQ (rejected: needless dependency).

**Consequences.** Requires lifecycle management (systemd / supervisor) and a
shared `/run/nui` runtime dir. `QLocalSocket` can't do SEQPACKET → UI uses
`QSocketNotifier` over the raw fd.
